一、总体结论
--------------------------------------------------------------------------------

工程基础扎实：采用 fail-loud 校验，不自动重投影；GeoPackage 字节确定性处理到位；输出先写
staging 目录再替换；免责声明较充分；SOURCES.md 的法源工作认真；核心算法模块 100% 分支覆盖。
问题主要集中在下面五个方面：

  1. 【规则口径】重叠"实质性"只看相对 1% 阈值。LCDB 单元最大 36,801 ha，1% 就是数百公顷，
     结果有 43 个进入候选队列的单元各含 ≥1 ha 已测绘 pre-1990 人工林（合计 990.9 ha，最大
     146.9 ha），22 个各含 ≥1 ha DOC 保护地（合计 660.1 ha，最大 297 ha）。README 把这些
     称作"边界碎片（sliver）"，与数据不符。
  2. 【规则口径】R-02 宽度规则在真实数据上等价于"2A/P ≥ 30 m"，erosion 从未决定过结果；而
     2A/P 系统性偏低，恰好 30 m 宽的直条带也会被判失败。pre-1990 证据只取了 LUCAS 72 类，
     漏掉了 71 类（天然林）。2025 年 LUC 1–6 外来林注册限制也没有写进规则登记册。
  3. 【安全】review_map.html 存在存储型 XSS（输入中任意属性值都能触发）；LINZ API key 可能被
     写进受版本控制的 HTML。
  4. 【人工复核环节】人工复核是项目自称"最薄弱环节"的唯一证据闸门，但：地图的说明面板因 JS
     报错从不显示；评审卡片上的十字标记有一半落在多边形外；固定的 30 个样本用当前代码无法复现，
     且 167 个 advisory 候选的入样概率为 0；标签校验可以用空白字符串绕过。
  5. 【可复现与溯源】上游原始数据没有归档；8 个已提交的二进制/HTML 产物跨环境会漂移但 CI 不检查；
     依赖没有锁定；manifest 缺少 git SHA、库版本和规则配置。

问题数量（去重合并后）: 高 7 项 / 中 19 项 / 低 11 项 / 信息 1 项

[H-01] review_map.html 存储型 XSS
  位置 : src/ets_screening/sample_review.py:97, :102
  问题 : 1) const features={json.dumps(geojson)} 直接嵌进 <script>。json.dumps 不转义
            "<" 和 "/"，所以任何属性里的 "</script>" 都会提前闭合脚本块，页面一打开就执行。
         2) popup 用字符串拼 HTML：'<b>'+f.properties.unit_id+'</b>...'，最终经 innerHTML
            渲染。
         3) 候选层的所有额外列（例如申请人提交的备注字段）会一路带进 review_queue 和 HTML。
            README 还建议使用 "applicant-supplied stand boundaries"，即输入可能来自利益相关方。
  证据 : SEC agent 用 Playwright + Chromium 实测：
           lcdb_class 含 </script><script>...  → 页面加载即执行
           unit_id 含 <img src=x onerror=...> → 点击 popup 后执行
           额外列 applicant_note 走完整条 ets-screen 流水线 → 加载即执行
         主审阅读源码确认了这两处注入点。
  影响 : 评估员一打开地图，脚本就在本地执行，可以篡改显示的状态，或把数据外发。
  解决 :
      def js(value) -> str:
          return (json.dumps(value).replace("<", "\\u003c").replace(">", "\\u003e")
                  .replace("&", "\\u0026").replace("\u2028", "\\u2028")
                  .replace("\u2029", "\\u2029"))
      # const features={js(geojson)};  L.tileLayer({js(tile_url)}, ...)
      # popup 用 DOM API 构造，不用字符串拼接：
      onEachFeature:(f,l)=>{const d=document.createElement('div');
        const b=document.createElement('b'); b.textContent=String(f.properties.unit_id);
        d.append(b, document.createElement('br'), 'Status: '+String(f.properties.status));
        l.bindPopup(d);}
    - 只导出必要字段：sample[["unit_id","lcdb_class","area_ha","status","geometry"]]
    - 加 CSP meta（default-src 'none'; img-src https://basemaps.linz.govt.nz data:; ...）
    - SEC agent 已在副本中验证：修复后 PoC 不再触发，55 个测试仍然全部通过。

[H-03] 重叠"实质性"只用 1% 相对阈值：大块冲突地进入候选队列，同时又有整单元被排除
  位置 : src/ets_screening/rules.py:98-112；rules/rule_register.csv（R-03、R-04）；
         README Finding 1
  问题 : material = (overlap > 1 m²) AND (overlap / unit_area ≥ 1%)。LCDB 单元面积从
         0.0001 ha 到 36,801 ha，"1%" 对应的绝对面积相差 8 个数量级，而森林地的法定最小面积
         只有 1 ha。同时结果是整单元二元化的：
           - 正向问题：大单元即使含上百公顷冲突地，只要占比 <1% 就算 candidate；而且
             rule_results.csv 里 R-03 记为 passed=True。
           - 反向问题：小单元会因为 <15 m 宽的边界碎片被整体排除。由于 DOC 图层 410 个要素里
             有 236 个是 marginal strip（沿水体的窄条），一条河岸保护带就能让整块私有农地被
             标为 excluded。
  证据（主审已复核前两条）:
      - 43 个 candidate_review 单元各含 ≥1 ha pre-1990 人工林，合计 990.9 ha；最大一例
        lcdb1000035378-part-11 含 146.9 ha（占 0.90%）
      - 22 个 candidate_review 单元各含 ≥1 ha DOC 保护地，合计 660.1 ha，最大 297.2 ha
      - README 称为 sliver 的 679.3 ha 中，有 668.6 ha（98.4%）集中在 25 个单元里，每个单元的
        重叠都 ≥1 ha；其中 654.5 ha 的重叠区内部有 ≥30 m 宽的核心，是成块的保护地，不是碎片
      - 反向例子：lcdb1000004902（1.78 ha）被一块 882 m²、处处 <10 m 宽的碎片整体排除；
        另有 65 个单元（3,237 ha）仅因 90.9 ha marginal strip 被排除
  影响 : README Finding 1 的核心论断（小比例重叠都是泛化碎片）被数据证伪；筛查结果在两个方向
         上都会出错。
  解决 :
    1) 加绝对面积下限：
         absolute_material_overlap_m2: float = 10_000.0   # 1 ha
         material = (area > min_m2) & ((pct >= min_pct) | (area >= absolute_material_overlap_m2))
    2) 算面积前先用形态学开运算去掉碎片（与 LCDB 镜像的 15 m 简化相匹配）：
         inter = geom.intersection(target)
         inter = inter.buffer(-7.5).buffer(7.5).intersection(geom)
    3) 根本做法：用 candidate.difference(overlay_union) 把冲突部分切出去单独处置，剩余部分
       重新跑 R-01/R-02，不再让整个制图单元二元化地通过或排除。
    4) advisory 情况在 rule_results.csv 中把 passed 写成 NA，不再写 True。
    5) 同步修改 README Finding 1 和 rule_register。

[H-04] pre-1990 证据只取 LUCAS 72/72，漏掉 71 类天然林【受影响单元数需确认】
  位置 : scripts/download_gisborne_data.py:205

[H-06] 候选重叠校验的容差小于浮点噪声，合法输入被误拒
  位置 : src/ets_screening/load.py:60-61
         overlap_area = float(frame.geometry.area.sum() - frame.geometry.union_all().area)
         if overlap_area > 1e-6: raise ...
  问题 : 两个约 1e9 m² 的浮点和相减，再与 1e-6 m² 的绝对容差比较。这个量级下 float64 的 ULP
         约为 2.4e-7，差值的符号和大小基本随机。完整数据集能通过，只是因为差值恰好为负
         （-1.96e-5）。
  证据 : 主审已复现：用项目自带数据 data/processed/gisborne_candidates.gpkg 取
         sample(frac=0.5, random_state=25)，报错
         "candidate polygons overlap by 0.000 m2"，而逐对求交的真实重叠面积是 0。
         GEO agent 测 30 个随机半数子集，11 个被误拒；QA agent 测 12 个 1500 要素子集，7 个被误拒。
  影响 : 用户对同一份数据取子区域（包括通过 ArcGIS 工具）时，约 1/3 的概率被拒，报错信息也没法
         据此排查。
  解决 : 改为基于空间索引的逐对精确检测，并在报错中列出冲突的 unit_id：
      import numpy as np, shapely
      geoms = frame.geometry.values
      left, right = frame.sindex.query(geoms, predicate="intersects")
      keep = left < right
      inter = shapely.area(shapely.intersection(geoms[left[keep]], geoms[right[keep]]))
      tol = np.maximum(1e-2, 1e-9 * np.minimum(shapely.area(geoms[left[keep]]),
                                                shapely.area(geoms[right[keep]])))
      bad = inter > tol
      if bad.any():
          pairs = list(zip(frame["unit_id"].iloc[left[keep][bad]],
                           frame["unit_id"].iloc[right[keep][bad]]))[:5]
          raise InputValidationError(f"candidate polygons overlap: {pairs}")
    - 已验证：真实子集 0 误报，真实重叠照常检出；耗时从约 5 s 降到约 1.9 s。
    - 补一个"真实坐标量级 + 随机子集"的回归测试。

[H-07] 上游原始数据未归档，processed 输入无法重新推导
  位置 : scripts/download_gisborne_data.py；data/checksums.sha256；.gitignore（data/raw/*）
  问题 : 1) 四个来源（Living Atlas 的 LCDB 镜像、MfE LUCAS、DOC PCL、Stats NZ）都是可变的
            实时 ArcGIS REST 服务。脚本不记录服务版本、lastEditDate、serviceItemId 或下载时间；
            raw 缓存被 gitignore 排除，没有 checksum，也没有归档。
         2) 即使上游数据完全不变，GPKG 的物理结构（rtree 节点、触发器 DDL）也随 GDAL 版本变化，

      where 条件、服务端返回的 ID 数量，以及 GDAL/GEOS/PROJ 版本。

[M-01] R-02 实际只由向下偏的 2A/P 决定；恰好 30 m 宽的条带判失败
  位置 : src/ets_screening/geometry.py:23, :35；src/ets_screening/rules.py:91；README Finding 2
  问题 : r02 = core_pass & ~(ap_pass != core_pass)，化简后就是 core_pass & ap_pass。真实数据中
         ap_pass ⇒ core_pass 恒成立，所以 R-02 通过当且仅当 2A/P ≥ 30 m。这与 README "erosion
         是主判据" 的说法不符。
         2A/P 用半周长近似中心线长度，对 W×L 矩形得 WL/(W+L) < W，对紧凑形状最多低估一半。
         另外，buffer(-15) 对恰好 30.000 m 宽的形状返回空，实际生效阈值约为 30.0015 m，
         而法条只排除宽度 < 30 m 的情形。
  证据 : 主审复核：erosion 通过而 2A/P 失败的单元 694 个，2A/P 通过而 erosion 失败的 0 个。
         合成用例：33×304 m 直条带（1.0 ha）→ 2A/P = 29.77 → quarantine；31×400 m → 28.77
         → quarantine。真实数据中 62 个"只因 R-02 失败"的单元里，有 28 个的等效矩形宽度
         ≥30 m 且有 erosion 核心。
  解决 :
    - 过渡方案：改用等效矩形宽度，把 erosion 作为必要条件，并给 erosion 加容差：
        def width_equivalent_rectangle(g):
            A, P = g.area, g.length
            disc = (P / 4.0) ** 2 - A
            return math.sqrt(A) if disc <= 0 else P / 4.0 - math.sqrt(disc)
        core = not g.buffer(-(half_width - 1e-3)).is_empty   # 或 .area > min_core_m2
        r02 = core & (width_eqrect >= threshold)
    - 长期方案：实现 MPI 中心线法的近似版本（骨架取最长路径作为中心线，每 20 m 做一条垂直
      截线取平均）。
    - README 中关于 erosion 是主判据的描述要同步更正。

[M-02] R-01/R-02 按单个 LCDB 单元判定，不合并相邻的可种植单元
  位置 : src/ets_screening/rules.py:88；下载脚本中的 explode 步骤
  问题 : 法定 1 ha 和平均宽度针对的是森林区域，不是土地覆盖制图单元。(c)(ii) 的 contiguity
         例外和 MPI 的 15 m 规则都要求把相邻区域一起考虑。rule_register 虽写了
         "adjacency is not tested"，但没有量化影响。
  证据 : 716 个可种植单元仅因 R-01（或 R-01 加 R-02）被隔离。其中 307 个与相邻可种植单元合计
         ≥1 ha，274 个紧挨 candidate_review 单元。例：lcdb1000417456（0.9987 ha）与一个
         16,345 ha 的候选单元共边，却被隔离。
  解决 : 先用 buffer(7.5)（对应 15 m 间距）把可种植单元合并成"造林块"，在块上检验 R-01/R-02，
         并输出 contiguous_plantable_ha 列：
      blocks = gpd.GeoDataFrame(geometry=[plantable.buffer(7.5).union_all().buffer(-7.5)],
                                crs=out.crs).explode(ignore_index=True)
      blocks["block_area_ha"] = blocks.area / 1e4
      pts = plantable[["unit_id"]].set_geometry(plantable.representative_point())
      hit = gpd.sjoin(pts, blocks, predicate="within")
      out["contiguous_plantable_ha"] = out["unit_id"].map(hit.set_index("unit_id")["block_area_ha"])
      out["r01_area_pass"] = (raw_area_ha >= 1) | (out["contiguous_plantable_ha"] >= 1)
