 一、总体结论
----------------------------------------------------------------------

这个项目的工程质量明显高于一般的数据分析仓库：
  - 所有头条数字都能从原始数据复现，committed 输出与独立重算 0 差异。
  - CI 的 CSV 门禁确实能失败，实测过删除、新增、CRLF 三种情况。
  - action 全部按完整 SHA 锁定；workflow 权限默认只读。
  - R 的负向测试质量高，变异体杀死率 16/19。
  - PySpark 端口的本地比对能真实通过。

没有发现计算错误，也没有"严重"级别的问题。问题集中在四个方面：

 1. 解读比证据说得更强（S-01 至 S-05）
    - 头条"三个地区占一半以上的下降"没有和"这三个地区原本就有一半的羊"做对照。
    - 2012 年以前的缺行被读成了"没有任何扣留"。
    - 前三名单、数字精度、"奶牛是否替代羊"这几处的措辞都超出了证据能支撑的范围。

 2. 文档漂移，自我声明与事实不符（D-01 至 D-06、R-04、L-01）
    - README 手抄的内容已经和报告、CHANGELOG 不同步。
    - "数字全部内联计算"、"所有主张都有来源"、"哈希对照 SOURCE.md 校验"这三条声明都不属实。
    - AI 使用说明的链接已经失效。
    - Databricks 截图展示的是修复前的错误输出。
    - 唯一可引用的 v0.2.0 已经包含后来更正过的内容。

 3. 静默失败的路径（R-01 至 R-05、P-01 至 P-03）
    - 当前数据上结果都对，但下次换数据或改代码时，有好几处会"不报错、给错数"。
    - 其中最严重的是 P-01：PySpark 端口遇到比例低于 1% 的坏行时，会静默改掉头条结论。

 4. 发布链路与供应链（C-01 至 C-03）
    - 发布 job 持有写权限，同时运行未锁版本的代码。
    - Quarto、runner 镜像和 Python 传递依赖的版本都在浮动。
    - gh-pages 分支和 tag 都没有保护。

S-01【高】头条"三个地区占一半以上的下降"没有按基数归一化
  位置：README.md:3, 11；index.qmd:192-194、271（图 1 标题）、907
  问题：这三个地区 2002 年本来就持有可测羊群的一半。如果各地按同一比例下降，
        它们自然也会占下降的一半左右。头条实际上主要反映的是地区规模。
  证据（主会话已复核）：
        地区                 占2002基数  占下降    本地降幅
        Canterbury           19.8%      22.0%     46.0%
        Southland            15.2%      17.9%     48.8%
        Otago                15.6%      14.0%     37.1%  <- 占下降低于占基数
        Manawatū-Whanganui   16.7%      13.9%     34.3%
    - 前三合计：占基数 50.6%，占下降 54.0%，只高出 3.4 个百分点。
    - 可测地区整体降幅 41.3%。
    - 按降幅排，最大的是 Northland 66.6%、Marlborough 52.3%、Waikato 49.3%、Southland 48.8%。
  影响：标题 "Where New Zealand's sheep went" 加上"三地占一半以上"，会让读者以为下降
        集中在这三地。这是整份报告的核心结论，却没有最基本的基准对照。
  解决方法：在 sheep_change 中增加三列，并在头条旁写明对照：
        sheep_change <- sheep_change |>
          mutate(base_share = 100 * y2002 / sum(y2002[!is.na(change)]),
                 fall_share = 100 * change / decline_sum,
                 excess_pp  = fall_share - base_share)
    - 头条可改写为："三地在 2002 年持有 50.6% 的羊，占下降的 54%；
      下降大体与规模成比例，只有 Canterbury 和 Southland 略超比例。"
    - 图 1 可以加一组"占基数"的对照点或参考线。
  来源：数据 agent

S-02【高】2012 年前的缺行就是未公布的数据，报告却说"2002–2011 没有扣留"
  位置：index.qmd:561-563（图 3 的 alt 文本 "Nothing is withheld from 2002 to 2011"）、
        568-592（抑制率图 2002–2011 显示为 0%）、626-633；README.md:50；
        R/checks.R:22-29（census_year_reported）
  证据：
    - 原始 CSV 每年行数（主会话已复核）：2002–2011 为 560–810 行，2012 起恒为
      880 行（44 个代码 × 20 个地区）。文件从 2012 年起才是完整矩形。
    - 2012 年以前没有一个显式的 0 值单元格。早年的导出同时省略了零值和扣留值。
    - 2012 年被标 C 的 51 个单元格，全部在 2012 年前至少有一年缺行（平均缺 8.2/10 年）。
    - 缺行年份的调和残差明显不为 0，数字就在项目自己的 outputs/reconciliation.csv 里：
      2003 年羊（缺 Nelson、Chatham）143,694；2006 年羊 100,653；
      2008 年羊（缺 Tasman）320,299；2002 年奶牛 1,789。
    - Chatham 的奶牛缺行其实是 0：2013 年后显式为 0，2007 年奶牛缺 Chatham 时残差恰为 0。
  影响：
    - 抑制率时间趋势图，以及"2012 峰值是 C 而不是质量问题"的叙事，把导出格式的
      变化当成了扣留行为的变化。
    - "cannot be determined from the extract"与项目自己的残差数据相矛盾。
    - census_year_reported 看不到缺行（2002 年普查的 Nelson 奶牛约 1,789 头也属于
      "普查年扣留"），所以"9 次"偏低。
    - 奶牛窗口把 Chatham 当成不可测。如果按 0 计，2002–2025 的结果应为 7/14（待确认）。
  解决方法：
    - 补全网格，把"未出现在导出中"作为第三类画进图 3：
        grid <- regions |>
          tidyr::complete(year, tidyr::nesting(area_code, region), livestock_class,
                          fill = list(suppressed = FALSE)) |>
          mutate(absent = is.na(head) & !suppressed)
    - alt 文本改为 "No cell carries a suppression flag from 2002 to 2011; rows are
      absent from the export in those years instead."
    - README.md:50 相应改写；在 census_year_reported 旁注明它不覆盖缺行。
  来源：数据 agent（文档 agent 独立指出 alt 文本比正文说得更确定）

S-03【中】前三名单不稳健：Otago 与 Manawatū-Whanganui 只差 1.6 万头
  位置：README.md:11、83；index.qmd:192、765-768
  证据：
    - Otago 下降 2,270,557 头，Manawatū-Whanganui（MW）下降 2,254,586 头，差 15,971 头。
      这个差距只有 Otago 2025 年存栏的 0.41%，而 Otago 仅 2024→2025 一年就降了 209,536 头。
    - 起点固定为 2002 年、终点换成 2018–2024 中任一年时，第三名都是 MW。
    - 设计匹配窗口（2002–2022）的前三是 Canterbury、Southland、MW，占 55.6%。
      README 只写了"the same qualitative answer"，没提名单变了。
  影响：头条点名的地区组合，在统计上与另一组合无法区分；点名 Otago 属于过度精确。
  解决方法：
    - 头条写成"Canterbury 和 Southland，其后 Otago 与 Manawatū-Whanganui 几乎并列
      （2.27M vs 2.25M）"。
    - README.md:83 改为 "...the top three (Canterbury, Southland, Manawatū-Whanganui)
      at 55.6 percent: still over half, though Otago drops to fourth."
    - 明确写出：份额是稳健的，名单不稳健。
  来源：数据 agent、文档 agent

S-04【中】没有任何不确定性量化，头条数字精度虚高
  位置：README.md:3、11（16.32M、53.6%、0.77%）；index.qmd:187-188、208-211
  证据：
    - 报告自己引用的 2025 年全国羊只相对抽样误差为 3%，换算成半宽约 ±0.7M 头。
    - 写成两位小数的 "16.32 million" 暗示精度约 ±5 千头，比置信区间窄约 140 倍。
    - 地区层面的抽样误差通常更大，但没有报告。
    - 敏感性分析中 West Coast 的"增长"来自噪声很大的 2025 端点：
      2023 年 15,339 → 2024 年 28,534 → 2025 年 52,542。
  影响：读者会把点估计当成精确值。
  解决方法：
    - 头条改为"约 16.3 million（按 Stats NZ 的 3% 抽样误差，约 ±0.7M）"。
    - 至少写一句"未量化不确定性；名次差距小于 X 时不作区分"。
    - 有条件的话，按地区抽样误差对前三份额做 Monte Carlo 区间。
  待确认：30% hot-deck 插补是否会让变化量偏向持平，需要看 Stats NZ 方法文档。
  来源：数据 agent

R-01【中】OBS_VALUE 的校验太宽：十六进制、小数、负数、科学计数法都能静默通过
  位置：R/load.R:137-144
  证据：
        mutate(head = suppressWarnings(as.numeric(obs_value)))
        if (any(!is.na(selected$obs_value) & !is.finite(selected$head))) stop(...)
    实测 load_livestock() 能接受 "0x1A"（变成 26）、"1.5"、"-5"、"1e3"（变成 1000）。
    负数之后会被 validate 规则拦下，但小数头数和十六进制在整条流水线里都没有检查。
    PySpark 端口同样会接受 "4192693.5"。
  解决方法：头数应当是非负整数，改成先检查原始字符串（已验证现有测试全部仍然通过）：
        bad <- !is.na(selected$obs_value) &
               (!grepl("^[0-9]+$", selected$obs_value) | !is.finite(selected$head))
        if (any(bad)) stop("Selected series contains a non-integer OBS_VALUE: ",
                           paste(utils::head(unique(selected$obs_value[bad]), 5),

C-01【中】发布 job 持有写权限并运行未锁版本的代码；线上页面是二次渲染；gh-pages 可以绕过门禁
  位置：.github/workflows/reproduce.yml:130-159
  证据：
    - publish job 有 `permissions: contents: write`，并在同一个 job 里依次执行
      renv::restore()（66 个包）、Rscript R/checks.R 和 quarto publish（会执行 index.qmd
      中的 R 代码）。
    - checkout 默认把 token 持久化在磁盘上。
    - gh-pages 分支没有保护（protected: false）。Pages 用的是"从分支部署"模式；09-04
      那几次部署就是作者手动推送 gh-pages 触发的，说明这条路径至今可用。
    - workflow 注释自己写着 "quarto publish gh-pages renders the project itself, so this
      repeats the render"。线上 HTML 来自第二次渲染，这份产物本身从未经过比对。
  影响：
    - 任何一个 CRAN 包、Quarto 或 action 被投毒，恶意代码都会在拿着写 token 的 job 里运行。
      它可以篡改线上页面、移动或删除没有保护的 tag v0.1.0 和 v0.2.0，或者修改 release。
    - "线上页面就是通过验证的那次构建产物"这个说法，严格来说不成立。
  解决方法：
    - 在 reproduce job 里上传已经验证过的 _site；新建 deploy job，只给 pages 和 id-token
      两个权限，不执行任何项目代码：
        - name: Upload the verified site
          if: github.event_name == 'push' && github.ref == 'refs/heads/main'
          uses: actions/upload-pages-artifact@<full-sha>
          with: { path: _site }
      deploy:
        needs: [reproduce, port]
        if: github.event_name == 'push' && github.ref == 'refs/heads/main'
        runs-on: ubuntu-24.04
        permissions: { pages: write, id-token: write }
        environment: { name: github-pages, url: ${{ steps.deployment.outputs.page_url }} }
        steps:
          - id: deployment
            uses: actions/deploy-pages@<full-sha>
    - 把 Settings → Pages → Source 改为 "GitHub Actions"；github-pages environment 只允许
      main 部署。
    - 删除 gh-pages 分支，或者用 ruleset 禁止更新它。
    - 给 v* 加 tag ruleset（禁止更新和删除），并开启 immutable releases。
  来源：CI agent
